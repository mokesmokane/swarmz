## 1. Purpose

A tile is named after its folder (`swarmz`, `swarmz-2`), which says where a
conversation runs and nothing about what it is doing. Like a chat client
naming its threads, each Claude conversation gets:

- a **title**: a few words for what it is about ("Phone: answer questions
  from the screen");
- a **recap**: a short paragraph of what has been done and what is next,
  shown in a tooltip on the desktop and on a long-press on the phone.

The agent writes both itself, because it is the one that knows. Every
session is told how at start, and it keeps the card current as the work
moves. Until it does, the first prompt stands in as the title.

Non-goals: a summary generated by a second model call (the agent in the
tile does it, at no extra cost); cards for shell tiles; a history of past
recaps; the messaging and status parts of the original ledger design.

## 2. The card

```json
"card": { "title": "Phone: answer questions from the screen",
          "recap": "Parsed the AskUserQuestion dialog in the tool and added a card on the phone. All tests pass; PR 1 is open. Next: the file-sharing spec.",
          "updatedAt": "2026-09-21T09:12:00Z", "by": "agent" }
```

- Lives on the tile's entry in `~/.swarmz/workspace.json` (a new `card`
  field on `TerminalDef`, carried through the `extra` map in Rust and
  `TerminalSettings` in TypeScript), so it persists, syncs to every Mac
  (shared-workspace rules unchanged) and is read by the tool for the phone.
- `title`: 1–60 characters, one line. `recap`: up to 600 characters, plain
  text, newlines allowed, no other control characters. Both trimmed; longer
  input is cut at the limit, never refused.
- `by`: `agent` (set through the CLI), `user` (typed on the desktop), or
  absent when there is no card. A `user` title is kept when the agent sets
  the card without `--title`; `--title` from the agent replaces it (the
  briefing tells the agent not to, unless asked).
- The tile's `name` is unchanged and still what `attach`, hooks and the
  registry use; the card is display only.

### 2.1 Fallback title

With no card, the title is the session's **first prompt**: the `prompt`
field of the first `UserPromptSubmit` hook event since the last
`SessionStart` (the hook log already records it), first line only,
whitespace collapsed, slash commands skipped, cut to 60 characters on a
word boundary with `…`. Both folds derive it (`agentState.ts` and the
tool's `agent`, checked by the shared `tests/fixtures/agent-status.json`).
With no prompt yet, the row shows the name as today.

There is no fallback recap: the tooltip shows the fallback title's full
first prompt, and the phone shows `lastMessage` as it already does.

## 3. Mac tool

### 3.1 `card`

```
swarmz card [--tile <id>] [--title <text>] [--recap <text>]   # set
swarmz card [--tile <id>]                                     # read
```

- The tile is `--tile`, else `SWARMZ_TERMINAL_ID` from the environment
  (every holder's shell exports it, so an agent never needs the id).
  Missing both: `usage`. A tile not in the workspace: `unknown_tile`.
- Setting: re-reads `workspace.json` (as `new` does, so a concurrent change
  is kept), merges the given fields into the def's `card` with `updatedAt`
  now and `by: "agent"` (a `user` title stays unless `--title` is given),
  bumps `sync.revision`, writes atomically, prints `{"v":1,"card":{…}}`.
  The desktop's stat poll adopts the file within `SYNC_STAT_MS`, its next
  save pushes it to the other Macs, and the phone's `watch` re-reads the
  workspace on its next tick.
- Reading prints the card, or `{"v":1,"card":null}`.
- Text arguments go through the same cleaning as `send`: control
  characters other than newline dropped, then the limits of §2.
- `card` joins the ssh gate's allow list, so the phone can set a title by
  hand (§5) and a remote tile's desktop can edit one over ssh.

### 3.2 Rows

`ls`/`watch` rows gain `title` (the card's, else the fallback of §2.1,
else null), `recap`, `cardAt`, `cardBy`. `watch` reports a change to any of
them like any other row change.

## 4. Telling the agent

### 4.1 The briefing

Hook script version 3. On `SessionStart` (and only then), the script
prints, after logging the event as before, a JSON reply Claude Code adds
to the conversation as context:

```json
{"hookSpecificOutput": {"hookEventName": "SessionStart",
  "additionalContext": "<contents of ~/.swarmz/briefing.md with <name> filled in>"}}
```

`~/.swarmz/briefing.md` is installed beside the script and overwritten on
each version bump (a user who wants their own keeps it by removing the
`# SWARMZ_BRIEFING_VERSION=` line at its top). The default says, in short:

> You are running in a swarmz tile named "<name>" alongside other agents.
> Keep your tile's card current with
> `~/.swarmz/bin/swarmz card --title "…" --recap "…"`: set a title after
> your first reply (a few words for what this conversation is about) and
> update the recap whenever you finish something, change direction, or
> are about to ask a question — two or three sentences of what is done and
> what is next. Do not change a title the user typed unless asked.

The instruction reaches every Claude session in a swarmz tile on every Mac
without touching any project's `CLAUDE.md`. A project that wants to add
rules (a naming scheme, what belongs in the recap) puts them in its own
`CLAUDE.md`; the briefing does not need to be repeated there.

### 4.2 Permission

Running `swarmz card` is a Bash call, so in modes that ask, Claude Code
would ask each time. The hook install adds two entries to
`permissions.allow` in `~/.claude/settings.json` when they are absent,
`Bash(~/.swarmz/bin/swarmz card:*)` and `Bash(swarmz card:*)`, and never
removes anything (the merge keeps foreign entries, as today). Auto mode
runs it without asking anyway.

### 4.3 Remote tiles

A tile whose home is another Mac runs its Claude there, where the hooks
and the tool are installed too (agent-state install already fans out), so
nothing changes: the card is written on the home Mac and reaches this one
through sync.

## 5. Desktop

- **Sidebar row.** First line: the title (card, else fallback, else the
  name), bold, truncated. Second line: the name and the folder basename,
  or the machine label and folder for a remote tile, as today. The status
  dot, badges and buttons are unchanged. Rename still edits the name.
- **Tab label.** The title, truncated to the current width; the name in
  its `title` attribute.
- **Tooltip.** Hovering a row for 400 ms opens a card (not the native
  tooltip, which cannot wrap): title; name · machine · folder; the recap,
  or the full first prompt when there is no card, or "No recap yet"; then
  "updated 3 m ago by Claude" / "by you". Hidden on mouse-out or any key.
- **Editing.** Double-click the title in the row to edit it inline (the
  same control as rename, next to it); saving writes `card.title` with
  `by: "user"`. An empty edit removes the user title, and the agent's or
  fallback title returns.
- **Attention.** A tile whose card was updated while its pane was not
  focused gets no extra marker; the existing unseen dot covers turns.

## 6. Phone

- Rows (Home chips, the tile list, the needs-you cards) show the title
  where they show `name` today; the name moves into the sub-line before
  the Mac or folder.
- The tile header shows the title, with the name in the second line.
- Long-press a row, or tap the title in the tile header, for a sheet with
  the recap (or `lastMessage` when there is none) and "updated … by …".
- **Edit title** in that sheet runs `card --title` for a user title.

## 7. Testing

- **Folds (TS + Rust):** the fallback title from the first prompt after
  each `SessionStart` (first line, collapsed, slash command skipped, cut on
  a word), shared fixture cases.
- **Tool (`cli.rs`):** `card` sets and reads; keeps a concurrent workspace
  edit; bumps the revision; respects a user title; cleans and cuts text;
  refuses an unknown tile; the gate allows it; rows carry the fields.
- **Hooks (Rust):** version 3 installs the briefing and the two allow
  entries once, keeps a user-edited briefing, and the script's
  `SessionStart` output is valid hook JSON with the name filled in.
- **Desktop (vitest):** sidebar shows title/fallback/name in that order;
  tab label; tooltip content; inline title edit writes a user card;
  `toWorkspace` round-trips `card`.
- **Phone (JVM):** rows and header show the title; the recap sheet; edit
  title runs `card`.
- **By hand:** open a tile, ask Claude anything, see the fallback title
  appear on the first prompt and Claude's own title after its first reply;
  hover for the recap; rename the title by hand and see the agent keep it.

## 8. Build order

1. Tool: `card`, row fields, the fold fallback in both languages with the
   shared fixture, gate entry.
2. Hooks: script version 3 with the briefing and the permission entries.
3. Desktop: row, tab, tooltip, inline title edit, `card` on the workspace
   types.
4. Phone: rows, header, recap sheet, edit title.

Each step stands alone: with 1 and 2 only, the phone already shows titles
in `ls` and the desktop still shows names.
